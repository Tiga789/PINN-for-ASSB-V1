# D16-P5A existing-model transfer evaluation package

## Purpose

This package implements **D16-P5A: ALL55 existing-model transfer evaluation** for QJW-2 / PINN-for-ASSB-V1.

It does **not** train a new model. It reads the D15 ALL55 P2Dlite-RG soft-label directory and evaluates predictions generated by existing D15 models, or it can call an existing project inference script through a command template.

D15 boundary reminder: P2Dlite-RG labels are **model-consistent soft labels**, not experimentally measured internal-state truth.

## Files in this package

```text
scripts/gv1_d16_p5a_transfer_eval.py
README_D16_P5A.md
scripts/gv1_run_d16_p5a_examples.ps1
configs/d16_p5a_seen_cells_template.txt
```

The package only adds files under `scripts/`, `configs/`, and a README. It does not overwrite ASSB baseline files, D9.6/D9.5.1, D12-S1K, D15_ALL55_FINAL, or old P4B/P5B/P5C outputs.

## Expected D15 input directory

```text
E:\XJTU battery dataset\_gv1_cache\xjtu_softlabels_p2dlite_rg_v1_D15_ALL55_FINAL
```

This directory should contain 55 cell folders and/or:

```text
D15_ALL55_SOFTLABEL_MANIFEST.csv
D15_ALL55_SOFTLABEL_SUMMARY.json
```

Each cell folder should contain one of:

```text
solution_softlabels.npz
solution_softlabel.npz
solution.npz
```

## Mode 1: preflight only

Run this first. It checks whether ALL55 labels are discoverable and writes a manifest.

```powershell
python scripts\gv1_d16_p5a_transfer_eval.py `
  --soft-label-root "E:\XJTU battery dataset\_gv1_cache\xjtu_softlabels_p2dlite_rg_v1_D15_ALL55_FINAL" `
  --output-root "E:\XJTU battery dataset\_gv1_cache\xjtu_d16_p5a_existing_transfer_preflight" `
  --preflight-only
```

Expected key outputs:

```text
d16_p5a_cell_manifest.csv
d16_p5a_softlabel_preflight.csv
d16_p5a_scorecard.json
```

Pass condition: `d16_p5a_scorecard.json` has `status = PASS` and discovers 55 cells.

## Mode 2: evaluate existing prediction.npz files

Use this when you already have predictions from an existing D15-P2 / Batch-2 / P3C model.

```powershell
python scripts\gv1_d16_p5a_transfer_eval.py `
  --model-name "D15_P2_8cell_existing_model" `
  --soft-label-root "E:\XJTU battery dataset\_gv1_cache\xjtu_softlabels_p2dlite_rg_v1_D15_ALL55_FINAL" `
  --prediction-root "E:\XJTU battery dataset\_gv1_cache\xjtu_d16_p5a_predictions_D15P2" `
  --output-root "E:\XJTU battery dataset\_gv1_cache\xjtu_d16_p5a_eval_D15P2_on_ALL55" `
  --projection-modes "raw,projected"
```

The script searches these prediction layouts:

```text
<prediction-root>\<cell_uid>\prediction.npz
<prediction-root>\<cell_uid>_prediction.npz
<prediction-root>\<original_cell_folder_name>\prediction.npz
```

## Mode 3: generate predictions by calling your existing inference script, then evaluate

Use this when you have an existing inference script from D15, but predictions have not yet been generated for ALL55.

Replace `scripts\YOUR_EXISTING_D15_INFER_SCRIPT.py` with the actual D15 inference entrypoint in your project.

```powershell
python scripts\gv1_d16_p5a_transfer_eval.py `
  --model-name "D15_P2_8cell_existing_model" `
  --soft-label-root "E:\XJTU battery dataset\_gv1_cache\xjtu_softlabels_p2dlite_rg_v1_D15_ALL55_FINAL" `
  --prediction-root "E:\XJTU battery dataset\_gv1_cache\xjtu_d16_p5a_predictions_D15P2" `
  --output-root "E:\XJTU battery dataset\_gv1_cache\xjtu_d16_p5a_eval_D15P2_on_ALL55" `
  --model-dir "E:\XJTU battery dataset\_gv1_cache\xjtu_d15_p2_existing_model_dir" `
  --run-inference `
  --inference-command-template "python scripts\YOUR_EXISTING_D15_INFER_SCRIPT.py --model-dir {model_dir} --soft-label-npz \"{soft_label_npz}\" --output-npz \"{output_npz}\" --device cuda:0" `
  --projection-modes "raw,projected"
```

Before running real inference, you can do a dry run to generate per-cell command logs without executing:

```powershell
python scripts\gv1_d16_p5a_transfer_eval.py `
  --model-name "D15_P2_8cell_existing_model" `
  --soft-label-root "E:\XJTU battery dataset\_gv1_cache\xjtu_softlabels_p2dlite_rg_v1_D15_ALL55_FINAL" `
  --prediction-root "E:\XJTU battery dataset\_gv1_cache\xjtu_d16_p5a_predictions_D15P2" `
  --output-root "E:\XJTU battery dataset\_gv1_cache\xjtu_d16_p5a_eval_D15P2_dryrun" `
  --model-dir "E:\XJTU battery dataset\_gv1_cache\xjtu_d15_p2_existing_model_dir" `
  --run-inference `
  --dry-run `
  --inference-command-template "python scripts\YOUR_EXISTING_D15_INFER_SCRIPT.py --model-dir {model_dir} --soft-label-npz \"{soft_label_npz}\" --output-npz \"{output_npz}\" --device cuda:0"
```

## Key outputs and how to read them

### 1. `d16_p5a_scorecard.json`

Top-level decision file.

Important fields:

```text
status: PASS / REVIEW / FAIL
cell_count_discovered
cell_count_evaluated
fail_metric_row_count
review_metric_row_count
failure_count
next_decision
```

Interpretation:

- `PASS`: existing model transfers to ALL55 according to current gates.
- `REVIEW`: runs completed, but some batch/cell/metric deserves manual review. This is common for transfer tests.
- `FAIL`: missing predictions, shape mismatch, or metrics clearly below threshold.

### 2. `d16_p5a_cell_metrics.csv`

One row per `(cell, projection_mode, metric)`. Start here for detailed diagnosis.

Important columns:

```text
cell_uid, batch, protocol, projection_mode, metric,
mae, rmse, max_abs, bias, corr, r2, nmae_range,
status, message
```

For D16-P5A, compare `raw` vs `projected`:

- If `projected` fixes theta out-of-bound without hurting MAE/corr, projection repair is working.
- If `raw` and `projected` are both poor, the old model probably does not transfer and D16-P5B is needed.

### 3. `d16_p5a_batch_metrics.csv`

Batch-wise aggregation. Use it to identify whether failures concentrate in Batch-2, Batch-5/6, or flagged Batch-1 battery-8.

### 4. `d16_p5a_protocol_metrics.csv`

Protocol-wise aggregation. Use it to check whether transfer fails for 3C, random-walk, GEO, R2.5, R3, etc.

### 5. `d16_p5a_seen_unseen_metrics.csv`

If you provide `--seen-cells configs\d16_p5a_seen_cells_template.txt`, this file separates seen vs unseen cells. Without a seen-cells file, the column is `unknown`.

### 6. `d16_p5a_failures.csv`

Any missing predictions, shape mismatch, or missing keys are listed here. The script defaults to **not** silently trimming mismatched arrays. Use `--allow-time-trim` only for deliberate debugging.

## Recommended D16-P5A decision rule

1. If old D15-P2 / Batch-2 models fail broadly across ALL55, move to **D16-P5B ALL55 unified NN training benchmark**.
2. If failures are localized, inspect by `batch`, `protocol`, `flagged`, and `raw/projected` before training a new model.
3. Do not claim held-out generalization from D16-P5A alone. Held-out evidence belongs to D16-P5C.
